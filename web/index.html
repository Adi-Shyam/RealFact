Other references used

  • FEVER: Thorne, Vlachos, Christodoulopoulos, Mittal, NAACL-HLT 2018. Gave us the retrieve-then-classify formulation and the SUPPORTED / REFUTED / NEI labels.
  • LIAR: Wang, ACL 2017. Short political statements on a six-way scale, collapsed to three classes.
  • FakeNewsNet: Shu et al., Big Data 2020. Full news articles with source URLs; the only benchmark that contains syndicated copies.
  • BGE / C-Pack: Xiao et al., 2023. BAAI/bge-small-en-v1.5, 384-d unit-normalised embeddings.
  • OpenMP API 5.2: #pragma omp parallel for schedule(runtime) with static / dynamic / guided schedules.
  • Roofline: Williams, Waterman, Patterson, CACM 2009. At 0.5 flop/byte the scan is memory-bound, which predicts where speedup will flatten.
  • HoVer, IMRRF: multi-hop evidence retrieval and reasoning for fact verification. Like the others, they report accuracy but not multicore latency.

Four differences you can see in this app

Difference 1 · retrieve wide, then cluster

Existing pipelines: top-K articles. RealFact: top-K independent stories.

If ten outlets syndicate one report and K = 10, a top-K list is ten copies of one story. Clustering after truncation leaves 9 empty slots. RealFact clusters the M = 10K pool first, so copies can't fill the slots.

Difference 2 · independence weighting

n syndicated copies count as 1 + λ·log₂ n, not n

λ = 0: one vote per cluster. λ → 1: approaches naive counting. The default λ = 0.5 gives 16 copies the weight of 3 votes, not 16.

Difference 3 · four-way verdict

Supported · Contradicted · Conflicting Evidence · Unverified

UnverifiedΣσ≠0 w·p < θ: not enough polar evidence
Conflictingδ < D < 1−δ: independent sources disagree
SupportedS ≥ 0 otherwise
ContradictedS < 0 otherwise

A binary fake/real classifier has to guess on a contested claim. RealFact reports the disagreement instead.

Difference 4 · measured parallel retrieval

Same answers, less time, on a stated machine

Every parallel run is checked against a non-OpenMP serial build and must return bit-identical article IDs, so the speedup never comes at the cost of different results.

Try it live: verify a claim, then press “Simulate syndication ×10” on any evidence card. The verdict table under the result shows how naive counting and filter-off retrieval (the existing approach) shift while RealFact's independence-weighted verdict holds.

End-to-end pipeline

Blue stages are this project's novel contributions

Retrieval (§II-B)

All vectors are unit-normalised, so cosine similarity reduces to a dot product. The scan is exhaustive and exact. We use brute force rather than ANN on purpose: an ANN index would change what is retrieved between configurations, which would mix a recall change into the speedup measurement.

si = cos(q, vi) = qᵀvi, vi ∈ ℝ³⁸⁴

Parallelisation (§II-E)

  • #pragma omp parallel for schedule(runtime) over the corpus index
  • Private top-M min-heap per thread, padded to a 64-byte cache line (no false sharing)
  • Serial merge of the P heaps, independent of N. We concatenate and use nth_element (O(P·M + M log M)) instead of the planned heap merge (O(P·M·log M)), with identical output. This cut the Amdahl serial fraction at 16 threads.
  • One contiguous row-major N × 384 float32 matrix, so each thread reads a unit-stride stream
  • Ties broken by index, so IDs are bit-identical across all configurations

Aggregation (§II-D)

wc = 1 + λ log₂ nc, λ ∈ [0, 1]
S = Σ wcpcσc / Σ wcpc D = Σσ=+1 wcpc / Σσ≠0 wcpc

σc ∈ {+1, −1, 0} is the NLI stance of cluster c's representative and pc its confidence. S is the net signed stance. D is the share of non-neutral weight on the supporting side.

Preprocessing (§I-C)

  • HTML / boilerplate stripping, whitespace normalisation, English-only filter
  • Exact-duplicate hash on (source domain, normalised headline), applied before embedding
  • BGE-small-en-v1.5, 512-token limit: an article is represented by its lead
  • Leakage control: a benchmark claim's own article is removed from the pool before the scan

Threats to validity (§III-E)

  1. Using the headline as the claim on FakeNewsNet is a proxy, and it biases the task toward claims checkable from a headline.
  2. Embedding similarity can't tell syndication from independent outlets reporting the same wire fact, so the filter's measured effect is an upper bound.
  3. FEVER-trained models can key on claim wording, so FEVER accuracy alone doesn't prove that retrieval is doing the work.
  4. The live corpus changes between runs, so timings are taken on a frozen snapshot.
  5. Observed in this prototype: NLI models label off-topic premises as “contradiction”. We gate evidence with a relevance floor (cos ≥ 0.68 by default, adjustable) before NLI.
Benchmarking arm: timing only, separate from the accuracy path

OpenMP scheduling × threads × corpus size

Each configuration gets 2 discarded warm-ups and 11 timed queries. We report the median and IQR, plus p95. T1 comes from a build compiled without OpenMP. Synthetic corpora are random unit vectors: retrieval cost depends only on N × d, not on the text.

Correctness

Self-test suite

Checks the engine against a NumPy reference, checks bit-exactness against the serial build across every schedule and thread count, and re-derives the aggregation equations by hand. Runs in about a second.
